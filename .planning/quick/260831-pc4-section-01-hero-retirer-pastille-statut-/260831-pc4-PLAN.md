Derivation for the widened gutter (shown for traceability — do not recompute at runtime, do not add a measurement/observer pass):

Solving the current CSS box model (padding `1.15rem`=18.4px, gap `1.1rem`=17.6px, columns `.92fr`/`1.08fr`) against the given measured baseline (dots' right edge x=44.6, gutter=3.7 viewBox units) backs out a grid container content width of ≈475.7px — and that value reproduces x=44.6 exactly, confirming the model.

Applying the same model with gap widened to `3.5rem` (56px) at the `sm:` breakpoint only (mobile stays `1.1rem`, since connectors are `hidden` below `sm:` anyway and mobile is single-column/row-gap, not the gutter this task is about — leaving mobile gap untouched removes all risk of a width-affecting side effect):

- content width available to columns = 475.7 − 2×18.4 (padding) − 56 (new gap) = 382.9px
- col1 (pill column, `.92fr` of 2fr total) = 0.46 × 382.9 = 176.1px
- dots' new right edge: (18.4 + 176.1) / 475.7 × 100 ≈ **40.9**
- card's new left edge / convergence x: 40.9 + (56/475.7×100) ≈ **52.7**
- resulting gutter ≈ 11.8%, matching the ≈12% target

Use these three numbers (40.9, 52.7, and the unchanged y's 18/50/82) as the new literal path/node coordinates. No further precision is expected or verifiable without a browser this session.
