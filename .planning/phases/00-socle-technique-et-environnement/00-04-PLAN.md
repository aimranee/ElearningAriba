<objective>
Deliver SOCLE-05: an automated gate that runs lint, type-check and build on every
pull request targeting `main`, using the same npm scripts a developer runs
locally. Record the delivery flow the gate belongs to, and declare the one part of
it that is applied outside this phase.

Purpose: SOCLE-05 promises a broken merge is blocked. A gate that runs different
commands than the developer runs is a gate that fails for reasons nobody can
reproduce.

Output: `.github/workflows/ci.yml`, a Node version pin, and `CONTRIBUTING.md`
recording the branch → preview → pull request → merge flow.

**No push.** The workflow file is committed locally and stops there. Pushing this
repository is owned by another party and is user-gated (D-15).

**External dependency, declared not done:** the branch-protection rule that makes
this gate *required* before merge is applied on the hosting side once the
repository is connected. This plan writes the gate; it cannot make it blocking.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted pull-request code → CI runner | A pull request can contain arbitrary code that the workflow executes |
| CI runner → repository secrets | Anything in scope for the runner is readable by the code it runs |
| repository → client | `CONTRIBUTING.md` is delivered to the client who owns the repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-16 | Elevation of privilege | `.github/workflows/ci.yml` trigger | mitigate | Trigger is `pull_request`, and the file is asserted to contain no `pull_request_target`; the latter would run fork code with repository secrets in scope |
| T-00-17 | Information disclosure | secrets reaching untrusted workflow code | mitigate | The workflow is asserted to contain no `secrets.` reference at all; the build's environment block carries only non-secret placeholders, asserted to contain no long token and no `eyJ` fragment |
| T-00-18 | Elevation of privilege | over-broad `GITHUB_TOKEN` permissions | mitigate | Top-level `permissions: contents: read` and nothing else; no write scope is granted |
| T-00-19 | Tampering | dependency substitution during CI install | mitigate | `npm ci` installs strictly from the committed `package-lock.json`; `npm install` is not used |
| T-00-20 | Spoofing | a broken change merged despite a red gate | transfer | Making the gate required is a branch-protection rule applied on the hosting side; task 2 declares it explicitly as an external dependency rather than leaving SOCLE-05 half-met and unstated |
| T-00-21 | Information disclosure | internal commercial detail in a client-owned repository | mitigate | Task 2 forbids and asserts the absence of day rates, margins, schedules and out-of-scope lot references in `CONTRIBUTING.md` (D-16) |
| T-00-SC | Tampering | GitHub Actions marketplace actions | mitigate | Only first-party `actions/checkout` and `actions/setup-node` are used; no third-party action is introduced, so there is no `[ASSUMED]`/`[SUS]` supply-chain item to gate |
</threat_model>
