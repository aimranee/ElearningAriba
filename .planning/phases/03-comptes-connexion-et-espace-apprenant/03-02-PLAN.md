<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → Supabase Auth endpoints | unauthenticated sign-up, sign-in, recover and verify calls |
| Google OAuth provider → Supabase Auth callback | a third party asserts an identity |
| repository → committed secrets | any credential written literally into `config.toml` or `.env.example` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `/auth/v1/token` sign-in | mitigate | `[auth.rate_limit] sign_in_sign_ups = 10` and `token_verifications = 10` per IP per five minutes; `minimum_password_length = 8` with `password_requirements = "letters_digits"` raises the offline-guess cost. No captcha (D-08) — accepted, because a captcha is an unsigned third-party dependency |
| T-03-11 | Denial of service | Auth outbound email | mitigate | `[auth.rate_limit] email_sent = 2` per hour caps mail-bombing through the sign-up and recover endpoints; the per-IP `consume()` guard is added on the reset route in plan 03-07 |
| T-03-16 | Spoofing | unverified email addresses | mitigate | `enable_confirmations = true` — an account cannot sign in before its address is proven, so a signed-up-with-someone-else's-address account is inert |
| T-03-04 | Tampering | OAuth redirect allow-list | accept (deferred to 03-06) | `additional_redirect_urls` at `config.toml:162` is `https` while `site_url` is `http`; carried deliberately per D-14 and checked when Google is wired in plan 03-06. Recorded as a comment in the file so it cannot be lost |
| T-03-17 | Information disclosure | committed OAuth secret | mitigate | `secret = "env(SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET)"` only; acceptance criteria assert no `googleusercontent` literal and no non-empty value in `.env.example` |
| T-03-18 | Information disclosure | private supports bucket | mitigate | `[storage.buckets.supports] public = false` — no anonymous object URL exists; the only read path is a server-generated signed URL (plan 03-08) |
| T-03-19 | Information disclosure | outbound mail during development | mitigate | No `[auth.email.smtp]` block; the local stack's collector receives everything (D-23). No real email leaves |
| T-03-SC | Tampering | package-manager installs | n/a | No `npm install` in this plan; zero new dependencies this phase (D-19) |
</threat_model>
