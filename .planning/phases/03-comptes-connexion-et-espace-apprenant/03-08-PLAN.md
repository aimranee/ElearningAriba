<objective>
`CPT-06` becomes true — the space shows the learner's own name and keeps five
honest empty states — and `CPT-07` ships its mechanism: a support is downloaded
through a signed, short-lived, non-shareable link, with entitlement checked
server-side before the link is ever minted.

Vertical slice: `/espace` (session) → `documents-list` → `GET
/api/documents/[id]` → entitlement read under RLS → service-role
`createSignedUrl` → redirect to the object.

Purpose: `espace/page.tsx:16` still hardcodes `PRENOM_MAQUETTE = "…"`. Its own
comment says Lot 3 replaces *the source*, not the copy. This is that plan.

Output: one local seed script, a service-role client, a query layer, a signed-URL
service, one route handler, one component, one rewritten page.
</objective>

`app.acces_support` row, and no administration surface of any kind is created
(D-02). The seed file lives under `supabase/seed/`, **not**
`supabase/migrations/`, so it is never pushed to a hosted project.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner session → `app.acces_support` | entitlement is decided entirely by RLS on `auth.uid()` |
| entitlement check → service-role storage client | the service key bypasses every access rule; ordering is the control |
| signed URL → the open internet | the URL itself is the credential and travels outside the session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
