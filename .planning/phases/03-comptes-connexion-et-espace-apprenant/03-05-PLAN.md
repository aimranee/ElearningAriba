Export `POST` only, with a scope comment: sign-up creates state, this file has
no GET and no list route, and the handler never returns anything about an
existing account beyond what the copy already says.

Parse the body with `inscriptionSchema.safeParse`. On failure return
`NextResponse.json({ errors }, { status: 422 })` with
`inscriptionIssuesToFieldErrors(parsed.error.issues)` — locale keys, never
messages.

On success call `supabase.auth.signUp` with `email`, `password`, and `options`
carrying `emailRedirectTo` built as `${serverEnv.NEXT_PUBLIC_SITE_URL}/api/auth/callback`
and `data` carrying `prenom`, `nom` and `profil_professionnel` (mapped from the
form's `profil` field). Do **not** put `role` into `data` — the trigger ignores
it, and passing it would look like an intended path. Add a `why:` comment
recording that `data` becomes `raw_user_meta_data`, which is
**client-controlled**, and that this is exactly why the trigger reads only those
three keys.

Map the Supabase error back to an existing locale key, never to the provider's
English message: a weak-password rejection (the server enforcing the plan 03-02
rule) maps to `motDePasseFaible` on the `motDePasse` field; anything else maps to
a form-level `rejetServeur`. Return `422` with the field-keyed shape for the
first, `502` with `{ errors: {} }` for the second — the same two shapes
`api/contact/route.ts` already uses, so the island's branch logic is unchanged.

**Account-enumeration discipline:** when the address is already registered,
Supabase returns a success-shaped response with no session and no confirmation
sent. Pass that through as the ordinary success response. Do **not** add a
"cette adresse est déjà utilisée" branch — that would turn `/inscription` into
an account-existence oracle on a public form. `inscription.succes.titre` —
*« Vérifiez votre boîte mail. »* — stays true either way. Record this as a
`why:` comment referencing D-A10, which established the same discipline for the
password-reset surface.

Add a per-IP guard using `consume()` from `src/lib/rate-limit.ts`, keyed on the
first `x-forwarded-for` entry, returning the **same** success body on refusal —
copying the shape at `api/contact/route.ts:39-43`. This sits in front of
Supabase's own `email_sent = 2` per hour and costs no dependency.

Do not declare `export const revalidate`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public visitor → `/api/auth/inscription` | unauthenticated, unthrottled-by-default write path that mints accounts and sends mail |
| client form `data` → `raw_user_meta_data` → trigger | client-controlled JSON crosses into a `security definer` function |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-16 | Spoofing | sign-up with someone else's address | mitigate | `enable_confirmations = true` (plan 03-02) — the account is inert until the address is proven; asserted by the `email_not_confirmed` criterion |
| T-03-30 | Information disclosure | account enumeration on `/inscription` | mitigate | The already-registered case returns the ordinary success response and the same body; asserted by the repeat-sign-up criterion (same status, same body, still one profile row) |
| T-03-13 | Elevation of privilege | `raw_user_meta_data` | mitigate | The route never sends `role` (asserted by grep) and the trigger never reads it (plan 03-01); a crafted body cannot mint an administrator |
| T-03-11 | Denial of service | mail flooding through sign-up | mitigate | Per-IP `consume()` guard returning the success shape, in front of Supabase's `email_sent = 2` per hour |
| T-03-01 | Spoofing | weak passwords | mitigate | `inscriptionSchema` (8 chars + a digit) at the boundary and `minimum_password_length = 8` / `password_requirements = "letters_digits"` at the auth server; the route maps the server's rejection to `motDePasseFaible` rather than surfacing the provider's English message |
| T-03-31 | Information disclosure | provider error text rendered to the visitor | mitigate | Every failure maps to an existing `inscription.erreurs.*` key; a criterion asserts no French literal and no `any` in the handler |
| T-03-29 | Denial of service | `/inscription` forced dynamic | mitigate | The page imports neither `session.ts` nor `supabase/server.ts`; asserted by grep and by the `○ /inscription` build-output criterion |
| T-03-SC | Tampering | package-manager installs | n/a | No `npm install`; zero new dependencies (D-19) |
</threat_model>
