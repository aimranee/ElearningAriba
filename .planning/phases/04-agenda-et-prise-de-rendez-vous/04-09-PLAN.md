<scope_rulings>
Binding rulings from the phase orchestrator — do not relitigate:
- **`app.type_rendez_vous` is the single source of truth** for label, duration, `tampon_minutes` and
  `prix_centimes`. `src/locales/fr/agenda.json` keeps only the bootstrap seed values (D-21/D-22 — the
  seed is how the table is populated on a fresh environment) and static marketing copy that is not a
  type attribute. Its `typesRendezVous` array stays byte-identical (the D-24 fence) and is read by no
  runtime consumer.
- **Do not add a type-creation flow and do not add a type-deletion flow.** Editing the seeded types
  is the whole of AGD-03; creation and deletion are not in the requirement wording and would widen
  the surface. The database already refuses both — no grant, no policy — and this plan must not
  request either.
- **`actif` and `ordre` are not part of AGD-03 and are not editable here.** The requirement names
  four attributes; ship four.
- **Zero new runtime dependencies.** No form library, no table library, no currency-input library.
  Hand-rolled on the inherited primitives.
- **CLAUDE.md's queryKeys/optimistic-updates rule is not applicable to this phase** — no TanStack
  Query is installed and the budget is zero. Use the `useState` status machine idiom, and note that
  an optimistic update is wrong here for the same reason it is wrong on a booking: the value that
  matters is the one the database accepted.
- **No dialog and no modal** (Lot 3's D-A4 continuity). Anything needing confirmation reveals in
  place.
- **Write-forbidden for the whole phase:** `src/app/globals.css`, the nine `src/components/ui/*.tsx`
  primitives, `src/components/layout/*`.
- **Never derive toward institutional blue.** Blue is Doctolib's territory in the French public's
  mind and reads administrative; violet/indigo is this product's differentiator.
- **Mobile is a constraint, not a variant** (`04-CONTEXT.md` § Mobile): 375 px design target, 320 px
  validation floor, 44 × 44 px touch targets, 16 px minimum input font, no horizontal scroll ever,
  primary action in the lower half, nothing critical revealed on hover alone.
- **French typography is checked on the rendered result** (`04-CONTEXT.md` § Culture et typographie):
  sentence case, `« … »` with `U+202F` inside, curly apostrophe `U+2019`, `U+00A0` before `:` and
  before `€` and `%`, accented capitals, vouvoiement. Prices render through `formatCurrency`; any
  hour shown in prose renders through `formatHeureProse`.
- **This plan runs alone.** The local Supabase stack, the database and the `.next` directory are
  shared and `.planning/config.json` sets `parallelization: true`; every plan in this phase is
  serialised, one wave per plan, and no D-26 gate is open while a sibling writes.
</scope_rulings>

Create `src/lib/validation/types-rendez-vous.ts` in the `contact.ts` idiom. It exports a zod schema
for a single type edit and a French-key error mapper. The schema accepts exactly five fields and
refuses anything else:
- `id` — a non-empty string; it addresses the row and is never itself editable, so it is not part of
  the editable payload semantically even though it travels in it;
- `libelle` — a trimmed non-empty string with a sane maximum length;
- `dureeMinutes` — a positive integer, mirroring the table's `check (> 0)`, with an upper bound that
  keeps a typo from declaring a nine-hour appointment;
- `tamponMinutes` — a non-negative integer, mirroring `check (>= 0)` (D-20);
- `prixCentimes` — a non-negative integer, mirroring `check (>= 0)`.
**Price is validated and transported in centimes, never in euros**, because the store holds centimes
and a euro round trip is where a factor-of-100 bug lives. The euro rendering happens at the UI edge
only, through `formatCurrency`. Mirroring the table's checks here is what turns an invalid value into
a French field error instead of a 500 from a constraint violation.

Extend `src/lib/agenda/admin-queries.ts` with the administrator's read of `app.type_rendez_vous`:
all rows ordered by `ordre`, through the session-scoped client, with **no application-level
predicate standing in for RLS** and the same `why:` comment the file already carries, naming
`supabase/tests/lot4_rls_reservation.sql` as the negative proof that guards the choice. The public
reader in `src/lib/agenda/types-rendez-vous.ts` filters on `actif`; this one does not, because the
administrator must be able to see and edit a type they have deactivated.

Create `src/app/api/admin/types-de-rendez-vous/route.ts`. It exports **`PATCH` only** — state that
in a method-surface comment, and state *why* the other verbs are absent: AGD-03 configures existing
types, so there is deliberately no `POST` and no `DELETE`, and the database backs that up with no
grant and no policy for either verb. Sequence:
1. `requireAdministrator()` before anything is parsed.
2. Parse the body with the schema; on failure return 422 with the field-error map.
3. `update` the addressed row through the **session-scoped** client, so the `type_admin_update`
   policy is the enforcing layer. Never use `src/lib/supabase/service.ts` — it has no legitimate
   caller in this phase.
4. An `update` that matches zero rows is not a success. Ask PostgREST for the updated
   representation and treat an empty result as a French `introuvable` refusal — an RLS-filtered
   `update` is silently a no-op, so a handler that only checks `error` would report success while
   changing nothing.
5. On success call `revalidatePath("/agenda")` and `revalidatePath("/reservation")`. This is
   load-bearing: `/agenda` is a static shell under `revalidate = 3600` (D-06), so without an explicit
   revalidation a new price would sit stale in front of buyers for up to an hour while the database,
   the booking RPC and the confirmation email all used the new one — exactly the two-sources
   divergence this surface exists to remove. `revalidatePath` does not make the route dynamic; the
   build must still show `○ /agenda`.
6. Never let a `PostgrestError` message, table name or column name reach the response; map every
   failure to a key in `src/locales/fr/admin.json`.

Add to `src/locales/fr/admin.json` the copy this section needs: the screen title and intro, the four
field labels (libellé, durée en minutes, temps tampon en minutes, prix), the save action, the success
and failure messages, the `introuvable` refusal, and one sentence stating plainly **what changing a
value does and does not do** — a new duration or buffer changes which slots are offered from now on,
and existing reservations keep the duration and price recorded when they were booked. Do not restate
keys plans 04-02, 04-06, 04-07 or 04-08 already added.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| learner or anonymous session → `PATCH /api/admin/types-de-rendez-vous` | a direct call at the price the booking RPC will record |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-58 | Elevation of Privilege | `PATCH /api/admin/types-de-rendez-vous` | mitigate | Three layers: `requireAdministrator()` before anything is parsed; the RLS policy `type_admin_update` evaluating `app.est_administrateur()` on a session-scoped write; and the middleware matcher already covering `/admin`. A learner's direct call changes nothing, asserted end-to-end and in `supabase/tests/lot4_rls_reservation.sql` |
| T-04-59 | Elevation of Privilege | inventing or destroying an appointment type | mitigate | No `POST` and no `DELETE` on the route, no create or delete affordance in the UI, and — the layer that actually holds — no `insert`/`delete` grant and no `insert`/`delete` policy on `app.type_rendez_vous` (plan 04-01). A learner cannot mint a 0 € type and an administrator cannot orphan a `reservation.type_id` |
| T-04-60 | Tampering | client-supplied price reaching a booking | mitigate | The booking body carries only `typeId` and `debut`; price, duration and buffer are read from this table inside `app.reserver_creneau`. Editing the table is therefore the only way to change a price, and it is admin-gated |
| T-04-61 | Tampering | a stale price shown to a buyer after a change | mitigate | The route calls `revalidatePath("/agenda")` and `revalidatePath("/reservation")` after a successful write, so the static shell cannot advertise a price the database no longer holds. | T-04-62 | Input Validation | a malformed duration or price producing a 500 | mitigate | `src/lib/validation/types-rendez-vous.ts` mirrors the table's own `check` constraints, so an invalid value is a French field error; a value with more than two decimals is refused rather than silently rounded |
| T-04-63 | Repudiation | a silent no-op reported as a saved change | mitigate | The handler asks for the updated representation and treats a zero-row result as a French `introuvable` refusal — an RLS-filtered `update` raises no error, so checking `error` alone would report success while changing nothing |
| T-04-64 | Information Disclosure | raw `PostgrestError` in an admin response | mitigate | Every failure maps to a key in `admin.json`; no Supabase message, table or column name is serialised |
| T-04-65 | Tampering | a price change rewriting what a learner already agreed to | accept | Deliberate: `app.reservation` snapshots `lieu` and derives `fin`/`fin_avec_tampon` at booking time, and the export reads the type label at read time. | T-04-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new dependencies — no form, table or currency-input library. `git diff package.json package-lock.json` must be empty; any install requires a blocking human legitimacy checkpoint against `04-RESEARCH.md` § Package Legitimacy Audit first |
