<objective>
Deliver the conversion itself: the learner picks a type, picks a slot, checks a recap, and commits —
three screens and one success surface — then sees the appointment in their space.

Purpose: this is the slice the whole phase exists for, and the one place where a wrong turn is
expensive. D-10 fixes the screen count because in Lot 7 the commit button becomes a payment; D-09
fixes the identity model; D-11 fixes what the learner may and may not do afterwards, and says so
early rather than letting them discover it later.

Output: the authenticated booking flow, the success surface, the sign-in return path for a chosen
slot, and the first real content in `/espace`'s "Mes prochains rendez-vous" card.
</objective>

<interfaces>
The commit path, from plan 04-04:

```
POST /api/reservation
  body:  { typeId: "decouverte" | "individuelle", debut: <ISO datetime string> }
  200:   { id, ... the values the success surface needs }
  401 / 422 / 429 / 409-semantics: { erreur: <leaf key of reservation.erreurs> }
         'creneau_indisponible'           -> reservation.erreurs.creneauIndisponible (EXISTING copy)
         'appel_decouverte_deja_reserve'  -> the new discovery-call key
GET /api/reservation/[id]/ics  -> text/calendar attachment, session-scoped, non-oracle 404
```

The learner read path, from plan 04-04: `src/lib/agenda/queries.ts` exports an RLS-filtered list of
the signed-in learner's upcoming non-cancelled reservations joined to `app.type_rendez_vous`,
returning the `QueryResult<T>` discriminated shape.

The slot handoff from plan 04-03: `src/components/agenda/agenda-booker.tsx` writes
`{ typeId, debut }` to `sessionStorage` under `CLE_CRENEAU_CHOISI`, the single constant exported
from `src/lib/agenda/creneaux.ts` together with the Zod schema for that payload and a typed
read/clear helper pair, and navigates to `/reservation`. **Import that constant; never re-type the
literal.** A second copy of the key would break the D-09 return path with no type error and no
failing build.

The appointment types, from plan 04-03: `src/lib/agenda/types-rendez-vous.ts` (server-only) reads
the `actif` rows of `app.type_rendez_vous` — `id`, `libelle`, `dureeMinutes`, `tamponMinutes`,
`prixCentimes`, `ordre` — through the anonymous cookie-free client, in the `QueryResult<T>` shape.
That table is the single source of truth; `agenda.json.typesRendezVous` is bootstrap seed input and
is read by nothing at runtime.
**The chosen slot never travels in the URL** — a `searchParams` read is what would make `/agenda`
dynamic and break D-06.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous visitor → `/reservation` | an unauthenticated request to a surface holding personal data |
| learner session → another learner's reservation id | horizontal access attempt on the confirmation surface and the `.ics` download |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-28 | Elevation of Privilege | `/reservation` and `/reservation/confirmation` | mitigate | Both are gated by `requireLearner()` in the redirect-before-markup shape, so a failed session redirects before any markup renders; RLS is the second, non-bypassable layer |
| T-04-29 | Information Disclosure | confirmation surface for another learner's id | mitigate | The read goes through the session-scoped `src/lib/agenda/queries.ts` with no application-level owner filter — RLS decides — and renders the same not-found surface for "unknown" and "not yours", so it is not an existence oracle |
| T-04-30 | Tampering | open redirect after sign-in | mitigate | The post-sign-in destination is one of two hardcoded literals (`/reservation` or `/espace`), chosen on the presence of a `sessionStorage` key. **No redirect URL is ever read from a query parameter or from storage**, so there is no redirect target an attacker can supply |
| T-04-31 | Tampering | forged `sessionStorage` slot | accept | The stored `{ typeId, debut }` is only a UI convenience: the server re-derives the instant inside `app.reserver_creneau` and rejects anything not currently free, so a forged value can at worst produce a French refusal message |
| T-04-32 | Elevation of Privilege | client-side price or duration | mitigate | Neither is sent to the server: the POST body carries only `typeId` and `debut`, and the price, duration and buffer are read from `app.type_rendez_vous` inside the RPC |
