<objective>
Deliver the conversion itself: the learner picks a type, picks a slot, checks a recap, and commits —
three screens and one success surface — then sees the appointment in their space.

Purpose: this is the slice the whole phase exists for, and the one place where a wrong turn is
expensive. D-10 fixes the screen count because in Lot 7 the commit button becomes a payment; D-09
fixes the identity model; D-11 fixes what the learner may and may not do afterwards, and says so
early rather than letting them discover it later.

Output: the authenticated booking flow, the success surface, the sign-in return path for a chosen
slot, and the first real content in `/espace`'s "Mes prochains rendez-vous" card.
</objective>

The commit path, from plan 04-04:

```
POST /api/reservation
  body:  { typeId: "decouverte" | "individuelle", debut: <ISO datetime string>, jeton?: <uuid> }
         jeton is the D-27 retention token, absent when the visitor never held one. It grants no
         right to book: the RPC uses it only to exclude the caller's own retention from its
         re-derivation, and releases it on commit.
  200:   { id, ... the values the success surface needs }
  401 / 422 / 429 / 409-semantics: { erreur: <leaf key of reservation.erreurs> }
         'creneau_indisponible'           -> reservation.erreurs.creneauIndisponible (EXISTING copy)
         'appel_decouverte_deja_reserve'  -> the new discovery-call key
GET /api/reservation/[id]/ics  -> text/calendar attachment, session-scoped, non-oracle 404
```

The learner read path, from plan 04-04: `src/lib/agenda/queries.ts` exports an RLS-filtered list of
the signed-in learner's upcoming non-cancelled reservations joined to `app.type_rendez_vous`,
returning the `QueryResult<T>` discriminated shape.

The slot handoff from plan 04-03: `src/components/agenda/agenda-booker.tsx` retains the slot through
`POST /api/creneaux/maintien` and writes `{ typeId, debut, jeton, expireLe }` to `sessionStorage`
under `CLE_CRENEAU_CHOISI`, the single constant exported from `src/lib/agenda/creneaux.ts` together
with the Zod schema for that payload, a typed read/clear helper pair, and `maintienRestant()`.
It then navigates to `/reservation` **without asking the visitor to sign in** (D-28).
**Import that constant; never re-type the literal.** A second copy of the key would break the D-28
return path with no type error and no failing build.

The retention endpoints, also from plan 04-03 — unauthenticated by design, IP rate-limited:

```
POST   /api/creneaux/maintien  { typeId, debut, jeton? } -> { jeton, expireLe } | { erreur }
DELETE /api/creneaux/maintien  { jeton }                 -> 200, idempotent
```

The appointment types, from plan 04-03: `src/lib/agenda/types-rendez-vous.ts` (server-only) reads
the `actif` rows of `app.type_rendez_vous` — `id`, `libelle`, `dureeMinutes`, `tamponMinutes`,
`prixCentimes`, `ordre` — through the anonymous cookie-free client, in the `QueryResult<T>` shape.
That table is the single source of truth; `agenda.json.typesRendezVous` is bootstrap seed input and
is read by nothing at runtime.
**The chosen slot never travels in the URL** — a `searchParams` read is what would make `/agenda`
dynamic and break D-06.
