<objective>
Build the booking commit: one POST route that validates at the boundary, calls the booking RPC as the
session's own identity, maps its typed outcome to a French locale key, and — only after the row is
committed — sends the learner their confirmation with a `.ics` attached and notifies the trainer.

Purpose: PostgREST maps the exclusion violation `23P01` to HTTP **400, not 409** (proven live against
this stack), so branching on status is structurally broken. This plan is where that trap is closed
once, in the only place that writes a reservation.

Output: the trainer video-link env var, a hand-rolled `.ics` builder with a shape assertion, an
`attachments` extension on the existing Resend transport, three email renderers, the booking
validation module, the learner-side query module, and two route handlers.
</objective>

```sql
app.reserver_creneau(p_type_id text, p_debut timestamptz, p_lieu text, p_jeton uuid default null)

-- security definer, granted to authenticated only, revoked from anon.
-- resultat is one of: 'non_authentifie' | 'type_inconnu' | 'creneau_indisponible'
--                   | 'appel_decouverte_deja_reserve' | 'ok'

-- re-derivation runs against the public view.
```

<scope_rulings>
Binding rulings from the phase orchestrator — do not relitigate:
- **The 15-minute retention is IN SCOPE (D-27)** — `04-CONTEXT.md` was amended with D-27, D-28 and
  D-29 after the first pass of these plans, and the earlier out-of-scope ruling is **withdrawn**. Its
  schema and RPCs come from plan 04-01 and its anonymous route from plan 04-03; this plan's job is
  narrow and exactly two things: **pass the token through to `app.reserver_creneau`**, and let the
  RPC's release-on-commit do the rest. There is still **no fourth `statut` value** — the retention is
  a separate table, never a reservation state. A slot taken while the learner was on the recap is
  still handled by the RPC returning `'creneau_indisponible'`, which this route maps to the existing
  French message and which plan 04-05 turns into a return to a refreshed slot list.
- **A lapsed retention is not an error path.** Do not add a "your hold expired" branch to this route.
  If the fifteen minutes ran out and nobody else took the slot, the commit simply succeeds; if
  somebody did, it is `'creneau_indisponible'` like any other collision. Inventing a third outcome
  here would be the retention becoming a source of truth, which D-27 and D-03 both forbid.
- **Never branch on an HTTP status for the booking write.** `23P01` surfaces as 400, not 409 —
  proven live. Branch on the RPC's `resultat` string. Any `if (error.code === "23P01")`, and any
  `.from("reservation").insert(...)` in TypeScript, is a defect.
- **Zero new runtime dependencies.** The `.ics` is hand-rolled — `ics` pulls `yup` into a zod-only
  codebase and `ical-generator` is outside the budget. `package.json` and `package-lock.json` must
  show a zero diff apart from the two npm `scripts` lines.
- **No new email sender and no new domain** — extend `src/lib/email/resend.ts` additively.
- **DO NOT add a JS test framework.** `scripts/check-ics.mjs` is a plain node script run through an
  npm script, exactly like `scripts/check-mock-content.mjs`.
- **CLAUDE.md's queryKeys/optimistic-updates rule is not applicable to this phase** — no TanStack
  Query, and an optimistic update is actively wrong for a booking commit, where only the database
  knows whether the slot is still free.
</scope_rulings>
