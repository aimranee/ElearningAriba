<objective>
Stand up the whole Lot 4 temporal model in Postgres: three availability tables, one reservation
table whose exclusion constraint makes double-booking impossible, and the two `security definer`
functions that are the only read and write paths. Apply the migrations, regenerate the types, and
prove the lock and the isolation with SQL negative tests.

Purpose: D-03 chose a database constraint precisely so "the application code does not have to be
right". Every later plan in this phase — public agenda, booking flow, admin back-office — reads or
writes through the objects this plan creates. Nothing else can start until they exist and their
generated types are committed.

Output: two additive migrations, a regenerated `src/types/database.types.ts`, and two SQL negative
test files under `supabase/tests/`.
</objective>

Create five tables in schema `app`. The first four are exactly per `04-RESEARCH.md` Pattern 1 and
Pattern 4; the fifth is the D-27 retention:

- `app.type_rendez_vous` — `id text primary key` (the `agenda.json` ids `decouverte` /
  `individuelle`), `libelle text not null`, `duree_minutes int not null check (> 0)`,
  `tampon_minutes int not null default 15 check (>= 0)` (D-20), `prix_centimes int not null default
  0 check (>= 0)`, `actif boolean not null default true`, `ordre int not null default 0`,
  `created_at`, `updated_at`.
- `app.disponibilite_hebdomadaire` — `id uuid pk default gen_random_uuid()`, `jour_semaine smallint
  not null check (between 1 and 7)`, `heure_debut time not null`, `heure_fin time not null`, `actif
  boolean not null default true`, timestamps, `check (heure_fin > heure_debut)`. Use `time`, never
  `timetz`. Add a `comment on column app.disponibilite_hebdomadaire.jour_semaine` stating the
  numbering is ISO-8601 `isodow` (1 = lundi … 7 = dimanche) and that `extract(dow)` must never be
  mixed in — this is Pitfall 5.
- `app.exception_agenda` — `id uuid pk`, `jour date not null`, `ouvert boolean not null default
  false`, `motif text not null default 'blocage' check (motif in ('blocage','ferie','ouverture'))`,
  `libelle text`, `heure_debut time`, `heure_fin time`, timestamps, `check ((heure_debut is null) =
  (heure_fin is null))` (both null = whole day) and `check (heure_fin is null or heure_fin >
  heure_debut)`. Plus `create unique index exception_agenda_ferie_unique on app.exception_agenda
  (jour) where motif = 'ferie'` — at most one ferie row per date. Carry a `comment on index` stating
  **why it stays partial and what that costs**: a total `unique (jour, motif)` would forbid a second
  partial `blocage` on the same day, which plan 04-06 explicitly supports ("block a partial range"),
  so the index must stay partial. The cost is that PostgREST cannot target it — a partial unique
  index carries an index predicate that `on_conflict` cannot express, and an upsert against it fails
  with `42P10`. Plan 04-02 therefore seeds holidays by **read-then-insert-missing**, never by
  upsert. Do not "fix" this by widening the index.
- `app.reservation` — `id uuid pk`, `utilisateur_id uuid references auth.users(id) on delete set
  null` (D-08), `type_id text not null references app.type_rendez_vous(id)`, `debut timestamptz not
  null`, `fin timestamptz not null` (the meeting end — what the `.ics` and the CSV "durée" carry),
  `fin_avec_tampon timestamptz not null` (D-03: the locked range includes the buffer), `plage
  tstzrange generated always as (tstzrange(debut, fin_avec_tampon, '[)')) stored`, `statut text not
  null default 'confirmee' check (statut in ('confirmee','en_attente_paiement','annulee'))` (D-07),
  `paiement_requis boolean not null default false` (D-07), `lieu text not null` (D-15, snapshotted
  at booking time), `ics_uid text not null unique`, `ics_sequence int not null default 0`,
  `annulee_le timestamptz`, timestamps, and `check (fin > debut and fin_avec_tampon >= fin)`.

Add the AGD-05 lock as a named table constraint: `constraint reservation_pas_de_chevauchement
exclude using gist (plage with &&) where (statut <> 'annulee')`. Bounds are half-open `'[)'` — Do
NOT use `'[]'`, which would make a 09:00–09:45 and a 09:45–10:30 appointment collide. Do NOT put an
interval addition inside the generated expression (`42P17 generation expression is not immutable`,
proven) — that is why `fin_avec_tampon` is its own stored column. Do NOT create `btree_gist`.

- `app.maintien_creneau` (D-27) — `id uuid pk default gen_random_uuid()`, `jeton uuid not null`,
  `type_id text not null references app.type_rendez_vous(id)`, `debut timestamptz not null`,
  `fin_avec_tampon timestamptz not null`, `plage tstzrange generated always as (tstzrange(debut,
  fin_avec_tampon, '[)')) stored`, `expire_le timestamptz not null`, `created_at timestamptz not null
  default now()`. Add `create unique index maintien_creneau_jeton_unique on app.maintien_creneau
  (jeton)` — one live retention per visitor token, so choosing a second slot replaces the first
  rather than letting one visitor hoard the grid. Add `constraint maintien_pas_de_chevauchement
  exclude using gist (plage with &&)` — **unqualified, with no `where` clause**: an exclusion
  constraint predicate must be `immutable` and `now()` is only `stable`, so expiry cannot live in the
  constraint. Expiry is enforced two ways instead, and both are required: every reader filters on
  `expire_le > now()`, and `app.purger_maintiens_expires()` physically deletes lapsed rows at the top
  of each retention transaction so a stale row can never block a legitimate new retention. Carry a
  `comment on table` stating D-27 plainly: **this table is the experience, not the truth** — it is
  advisory, it is invisible to `app.reservation`'s constraint, and nothing may ever be allowed to
  depend on it for correctness. No `updated_at` and therefore no `touch_updated_at` trigger.

Add D-12 as `create unique index reservation_un_seul_appel_decouverte on app.reservation
(utilisateur_id) where type_id = 'decouverte' and statut <> 'annulee'`.

Attach `app.touch_updated_at()` as a `before update … for each row` trigger on all four tables. Do
not recreate that function.

Create seven functions, every one `security definer` with `set search_path = ''` and every
identifier fully qualified (Pitfall 6):

- `app.est_administrateur() returns boolean language sql stable` — `exists (select 1 from app.profil
  p where p.utilisateur_id = (select auth.uid()) and p.role = 'administrator')`.
- `app.paques(annee int) returns date language sql immutable` — the anonymous Gregorian computus in
  `04-RESEARCH.md` § Code Examples, verified against 2024–2028. Consumed by plan 04-02's seed.
- `app.creneaux_libres(p_type_id text, p_du date, p_au date, p_jeton uuid default null) returns table
  (debut timestamptz, fin timestamptz) language sql stable` — from `04-RESEARCH.md` Pattern 3, with
  one addition: after the `app.reservation` anti-join it also anti-joins `app.maintien_creneau` on
  `expire_le > now() and (p_jeton is null or m.jeton is distinct from p_jeton)` (D-27). The defaulted
  fourth parameter is what lets the holder keep seeing their own retained slot while it is hidden
  from everyone else; a caller that passes nothing sees the public view. Adding it as a **defaulted**
  parameter rather than a new function keeps every existing three-argument call site working.
  Otherwise verbatim: It enforces the
  D-13 window as SQL literals (`greatest(p_du, today Paris)`, `least(p_au, today + interval '8
  weeks')`, `debut >= now() + interval '24 hours'`), joins `disponibilite_hebdomadaire` on
  `extract(isodow from jour)`, subtracts whole-day and partial-day `exception_agenda` closures,
  adds `ouvert` exception ranges, steps each declared range by `duree_minutes + tampon_minutes`
  (D-04), and anti-joins `app.reservation` on `statut <> 'annulee'`. It returns **only free
  instants** — never a per-day status enum, which would publish the trainer's activity volume and
  break D-23.
- `app.purger_maintiens_expires() returns int language plpgsql volatile` — `delete from
  app.maintien_creneau where expire_le <= now()`, returning the deleted row count. This is the D-27
  sweep. It is called inline at the top of `app.maintenir_creneau` and `app.reserver_creneau` rather
  than from a scheduler, so the phase adds **no cron, no scheduled job and no hosted dependency** —
  every path that could be blocked by a stale retention purges first, in its own transaction.
- `app.maintenir_creneau(p_type_id text, p_debut timestamptz, p_jeton uuid default null) returns
  table (resultat text, jeton uuid, expire_le timestamptz) language plpgsql volatile` — D-27. In
  order: call `app.purger_maintiens_expires()`; resolve `p_jeton`, generating a fresh
  `gen_random_uuid()` when it is null; `delete from app.maintien_creneau where jeton = <that token>`
  so one visitor never holds two slots; re-derive `p_debut` from `app.creneaux_libres(p_type_id,
  (p_debut at time zone 'Europe/Paris')::date, (p_debut at time zone 'Europe/Paris')::date, <that
  token>)` and return `'creneau_indisponible'` when the instant is not there. **Both bounds must go
  through `at time zone 'Europe/Paris'`.** A bare `p_debut::date` resolves in the session `TimeZone`,
  which is UTC on Supabase, so any instant before 01:00 or 02:00 Paris lands on the previous UTC date
  and the re-derivation looks in the wrong day — a spurious `'creneau_indisponible'`. It is latent
  against the seeded 09:00–17:00 week and goes live the moment a trainer declares an early range
  through `/admin/horaires`. This is the same class of defect as `dow` vs `isodow` (Pitfall 5); read `duree_minutes + tampon_minutes` from `app.type_rendez_vous` (never from a
  parameter) to compute `fin_avec_tampon`; insert with **`expire_le = now() + interval '15 minutes'`
  as a SQL literal — the window is never read from a parameter**, or a client would grant itself an
  eight-hour hold. Catch `exclusion_violation` and return `'creneau_indisponible'`. Return
  `'type_inconnu'` for an unknown type and `'ok'` with the token and the expiry otherwise. It writes
  nothing to `app.reservation` and reads no session identity — a visitor has no account at this point
  (D-28).
- `app.liberer_creneau(p_jeton uuid) returns table (resultat text) language plpgsql volatile` —
  deletes that token's retention and returns `'ok'` whether or not a row existed. Idempotent by
  design: the browser calls it on abandon and on `beforeunload`, where a retry is normal and an error
  would be noise.
- `app.reserver_creneau(p_type_id text, p_debut timestamptz, p_lieu text, p_jeton uuid default null)
  returns table (resultat text, reservation_id uuid) language plpgsql volatile` — from
  `04-RESEARCH.md` Pattern 5, with the D-27 seam added as a **defaulted fourth parameter** so no
  existing call site breaks. It calls `app.purger_maintiens_expires()` first, passes `p_jeton`
  through to its `app.creneaux_libres` re-derivation so the caller's own retention does not hide the
  slot from them, and on `'ok'` performs **release-on-commit**: `delete from app.maintien_creneau
  where jeton = p_jeton`, in the same transaction as the insert. Carry a `comment on function`
  stating that the retention is an input to nothing but the re-derivation's anti-join: it grants no
  right to book and the exclusion constraint is still what decides (D-03, D-27).
  Reads the caller from `(select auth.uid())` and NEVER from a parameter. Returns
  `'non_authentifie'`, `'type_inconnu'`, `'creneau_indisponible'` (both when the re-derivation from
  `app.creneaux_libres` inside the same transaction does not yield `p_debut`, and when
  `exclusion_violation` fires), `'appel_decouverte_deja_reserve'` on `unique_violation`, or `'ok'`
  with the new id. It writes `statut` and `paiement_requis` at their column defaults — Lot 4 always
  writes `confirmee` (D-07). `ics_uid` is `gen_random_uuid()::text || '@formation-sap-ariba.fr'`.
  Do NOT use `pg_advisory_xact_lock` and do NOT use `select … for update` — both are anti-patterns
  named in the research; the exclusion constraint is the mechanism.

Enable RLS on all four tables and add the policies from `04-RESEARCH.md` Pattern 4:
`reservation_self_select` (`for select to authenticated using (utilisateur_id = (select
auth.uid()))`), `reservation_admin_all` (`for all to authenticated` using and with check

Enable RLS on `app.maintien_creneau` and give it **no policy whatsoever**, for any role. Combined
with the withheld table grants in Task 2, that makes the three definer RPCs its only reachable path.
Carry a `comment on table` saying why the absence is deliberate: a readable retention table would
tell a visitor *why* a slot is missing — someone is about to take it — which is exactly the activity

One more policy, for AGD-03: `type_admin_update` (`for update to authenticated`, using and with

duration, buffer time and price"; it does not ask for creating or destroying types, and both seeded
ids are referenced by `app.reservation.type_id`. Carry a `comment on policy` saying so, so the
absence of the other two verbs reads as a decision rather than an omission. This policy plus the

`tampon_minutes` and `prix_centimes`: `src/locales/fr/agenda.json` is bootstrap seed input only

Every non-obvious column and every constraint carries a `comment on` naming the decision it serves
