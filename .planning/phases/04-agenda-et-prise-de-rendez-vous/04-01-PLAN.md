<objective>
Stand up the whole Lot 4 temporal model in Postgres: three availability tables, one reservation
table whose exclusion constraint makes double-booking impossible, and the two `security definer`
functions that are the only read and write paths. Apply the migrations, regenerate the types, and
prove the lock and the isolation with SQL negative tests.

Purpose: D-03 chose a database constraint precisely so "the application code does not have to be
right". Every later plan in this phase — public agenda, booking flow, admin back-office — reads or
writes through the objects this plan creates. Nothing else can start until they exist and their
generated types are committed.

Output: two additive migrations, a regenerated `src/types/database.types.ts`, and two SQL negative
test files under `supabase/tests/`.

- `app.creneaux_libres(p_type_id text, p_du date, p_au date) returns table (debut timestamptz, fin
