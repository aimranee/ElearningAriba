<interfaces>
⚠ **The primitive layer is Base UI, not Radix.** `src/components/ui/button.tsx`
imports `@base-ui/react/button`; `@base-ui/react@1.7.0` is the dependency and its
`exports` map includes `./button`, `./accordion`, `./collapsible`, `./field`,
`./fieldset`, `./input`. There is **no Radix dependency, no `Slot`, no `asChild`**
anywhere in the repository. Base UI uses a `render` prop. Shipping a Radix
component here would create two incompatible primitive layers.

The template every family copies — `src/components/ui/button.tsx`:
- `import { X as XPrimitive } from "@base-ui/react/<part>"`, `import { cva, type VariantProps } from "class-variance-authority"`, `import { cn } from "@/lib/utils"`
- `const xVariants = cva("<base string>", { variants: { variant, size }, defaultVariants: { … } })`
- `function X({ className, variant = "default", size = "default", ...props }: XPrimitive.Props & VariantProps<typeof xVariants>)` — a `function` declaration, **not** `const` + arrow, **not** a default export
- every rendered root carries `data-slot="<kebab-name>"`, one per part in a multi-part family
- `className` threaded **into** `cva(...)` as the last key so `twMerge` resolves conflicts
- named export block at the bottom: `export { X, xVariants }`
- **no semicolons, double quotes** — that is the generated-component style inside `src/components/ui/`; keep it, even though every hand-written file elsewhere in `src/` uses semicolons. There is no Prettier config in the repo.
- **no `"use client"`** — these three families are presentational and stay server-importable

The state vocabulary already encoded in `button.tsx:7`, to be reproduced across
the families:

| D-23 state | Existing mechanism |
|---|---|
| default | `defaultVariants` |
| hover | `hover:bg-primary/80` |
| focus-visible | `focus-visible:border-ring focus-visible:ring-3 focus-visible:ring-ring/50` |
| active | `active:not-aria-[haspopup]:translate-y-px` |
| disabled | `disabled:pointer-events-none disabled:opacity-50` |
| error | `aria-invalid:border-destructive aria-invalid:ring-3 aria-invalid:ring-destructive/20` |
| loading | ⛔ **no precedent — invent it**: a `data-loading` attribute plus a `[&_svg]` spinner, matching the file's existing `data-*` / `[&_svg]` idiom rather than a boolean prop that leaks into markup |
| parent-context reaction | `in-data-[slot=button-group]:rounded-lg` — the `in-data-[slot=…]` idiom; the density contract reuses it as `in-data-[density=compact]:` |
| icon slots | `has-data-[icon=inline-end]:pr-2` |

Tokens available from plan 01-02: `--color-primary`, `--color-success`,
`--color-success-foreground`, `--color-success-muted`, `--color-destructive`,
`--color-ring`, `--color-border`, `--color-muted`, `--shadow-1` … `--shadow-4`,
