| Boundary | Description |
|----------|-------------|
| user input → form field | the field family renders untrusted text; Lot 2 and Lot 3 add the validation and submission behind it |
| server rejection → learner | a rejection the browser cannot predict must be legible, not silent |
| npm registry → repository | any new primitive package would cross a supply-chain boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-19 | Tampering | untrusted text rendered by field and empty-state parts | mitigate | Every string arrives as a React child or prop and is escaped by React; ⛔ no task may introduce `dangerouslySetInnerHTML` anywhere in these files |
| T-01-20 | Repudiation | a server-side rejection swallowed silently | mitigate | `data-rejected="server"` is a named state that always renders `FieldError` → `Message variant="error"` with `role="alert"` / `aria-live="polite"`, so a rejection is both visible and announced |
| T-01-16 | Denial of Service | keyboard-only users locked out of the accordion and forms | mitigate | The accordion trigger is a real `button` with `aria-expanded` / `aria-controls`; every control keeps the three-class `focus-visible` ring. Acceptance criteria assert both |
| T-01-21 | Information Disclosure | validation logic leaking business rules into the client bundle | mitigate | ⛔ No validation function, no `zod` schema and no rule lives in these presentational files; acceptance criteria assert the absence of `onSubmit`, `fetch(`, `"use server"` and any `zod` import (D-41) |

| T-01-NOINDEX | Information Disclosure | unfinished UI publicly reachable | accept | Production carries `X-Robots-Tag: noindex, nofollow` and holds no real data. ⛔ No task here may modify `next.config.ts` or `vercel.json` |
</threat_model>
