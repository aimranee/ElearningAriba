<task type="auto">
  <name>Task 1: A minimal dependency-free PDF writer</name>
  <read_first>
    - package.json (confirm no pdf dependency exists; none is to be added)
    - src/lib/utils.ts (the project's utility conventions)
    - CLAUDE.md (no `any`, comments explain why)
  </read_first>
  <action>
    Create `src/lib/pdf/writer.ts` — a minimal PDF 1.4 generator with no dependency. It
    exposes a builder taking an ordered list of typed text runs (each with x, y, font size,
    weight and the string) plus a page size, and returns a `Uint8Array`.

    Implementation points that must be explicit:
    - Objects: Catalog, Pages, one Page per rendered page, one Contents stream per page, and
      two Type1 base-14 font objects — Helvetica and Helvetica-Bold. Base-14 fonts need no
      embedding, which is why this is tractable without a library.
    - `/Encoding /WinAnsiEncoding` on both font objects. French copy uses é, è, ê, à, â, ç, î,
      ï, ô, û, ù and the « » guillemets, all of which exist in WinAnsi. Encode the string to
      WinAnsi bytes rather than UTF-8, and escape `(`, `)` and `\` inside literal strings.
    - A real xref table with correct byte offsets and a trailer with `/Size` and `/Root`,
      terminated by `startxref` and `%%EOF`. A wrong offset makes the file unopenable — the
      acceptance criterion below opens the output, it does not merely check the header bytes.
    - A page-break helper so content longer than one page continues onto a second.
    - Page size A4 in points: 595.28 x 841.89.

    Add a `why` comment recording that a dependency-free writer was chosen over a PDF library
    because this lot needs text-only output from five rows, and the base-14 Helvetica +
    WinAnsi path covers every character in the signed French. Never use `any`.
  </action>
  <acceptance_criteria>
    - `grep -n "WinAnsiEncoding" src/lib/pdf/writer.ts` matches on both font objects.
    - `grep -n "startxref" src/lib/pdf/writer.ts` and `grep -n "%%EOF" src/lib/pdf/writer.ts` both match.
    - `grep -rn "pdfkit\|pdf-lib\|jspdf\|puppeteer" package.json src/` returns zero lines.
    - `grep -c "\bany\b" src/lib/pdf/writer.ts` returns 0; `npm run lint` exits 0.
    - A smoke render writes a file that a PDF reader opens: `node --experimental-strip-types -e "..."` or an equivalent script produces `/tmp/smoke.pdf` whose first eight bytes are `%PDF-1.4` and whose byte length exceeds 800.
  </acceptance_criteria>
  <verify>
    <automated>npx tsc --noEmit &amp;&amp; npm run lint &amp;&amp; ! grep -rn "pdf-lib\|pdfkit\|jspdf" package.json</automated>
  </verify>
  <done>A typed PDF writer emits valid, openable single- and multi-page documents with correctly encoded French, with no dependency added.</done>
</task>
