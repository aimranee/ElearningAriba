    `section_cle text not null references app.content_section(cle) on delete cascade`,
    `cle text not null`, `titre text`, `description text`, `picto text`,
    `duree_heures integer`, `statut text`, `position integer not null`,

    `updated_at timestamptz not null default now()`,

    `sum(duree_heures)` computed at read time, never a stored string (D-30). `donnees` holds
    the per-page arrays that do not deserve their own table (`objectifs`, `contenu`,
    `deroule`, `fourni`, `question`, `reponse`). No tenant or organisation column (D-44).

    Create `app.contact_message`: `id uuid primary key default gen_random_uuid()`,
    `nom text not null`, `email text not null`, `telephone text`, `profil text not null`,
    `message text not null`, `created_at timestamptz not null default now()`. No delete
    policy and no delete route are created here — deletion and export are Lot 5's RGPD work
    (D-37).

    Enable row level security on all three tables. Policies (D-28):
    - `content_section_anon_select` — `for select to anon using (publie = true)`
    - `content_item_anon_select` — `for select to anon using (publie = true)`
    - `contact_message_anon_insert` — `for insert to anon with check (true)`, and NO select,
      update or delete policy for `anon` on that table.
    Grant `select` on the two content tables and `insert` on `app.contact_message` to `anon`,
    plus `usage` on schema `app` to `anon`, since RLS alone does not confer table privileges.

    Add an `updated_at` trigger function `app.touch_updated_at()` and attach a
    `before update` trigger to both content tables. Add `comment on table` for all three.

    Do not create indexes beyond the two unique constraints — the whole content set is under
    50 rows.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser -> Supabase PostgREST | Untrusted callers hold the anon key and can issue arbitrary reads and inserts limited only by RLS |
| seed script -> Supabase | Runs with the service-role key, which bypasses RLS entirely |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information disclosure | app.contact_message | mitigate | RLS enabled with an insert-only anon policy and no select policy; asserted by a grep gate in Task 1 |
| T-02-02 | Information disclosure | app.content_section / content_item | mitigate | anon select restricted to `publie = true`, so unpublished drafts never leave the database |
| T-02-03 | Tampering | anon write to content tables | mitigate | no insert/update/delete policy granted to anon on either content table; the seed uses the service-role key from server-only code |
| T-02-04 | Elevation of privilege | SUPABASE_SERVICE_ROLE_KEY | mitigate | key stays in `scripts/seed-content.mjs` (Node, never bundled) and `src/lib/env/server.ts`; `src/lib/supabase/public.ts` imports `server-only` and reads the anon key exclusively |
| T-02-05 | Denial of service | unbounded anon reads | accept | content set is under 50 rows, static/ISR rendering means Vercel serves cached HTML rather than hitting PostgREST per request |
</threat_model>
